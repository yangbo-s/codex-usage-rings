# 实现与验收

版本：0.4，2026-10-03。本文保留既有需求编号，更新到用户当前要求，不沿用初版演示行为。

## 目标、需求和门禁

GOAL-001：提供能在本机使用的低耗电 Codex 多账户菜单栏用量工具。

| 需求 / 验收 | 优先级 | 可观察行为 |
| --- | --- | --- |
| REQ-001 / AC-001 | P1 | 初始一个连接入口，本机已登录则自动成为真实账户环；每连接一个账户增加一个环，无演示模式 |
| REQ-002 / AC-002 | P1 | 中心显示剩余百分比数值（无 %）；长额度外环、5 小时内环；只有一个窗口时为粗单环；详情显示两种数值与重置时间 |
| REQ-003 / AC-003 | P1 | 账户昵称与来源持久化，旧演示记录迁移剔除；移除最后一个账户后不自动加回 |
| REQ-004 / AC-004 | P1 | 本机登录只读复用；额外账户隔离登录；失败保留快照，未知不冒充 0% |
| REQ-005 / AC-005 | P1 | 可构建、签名并启动 .app，完成测试与原生界面检查；未取得的交互证据明确披露 |
| REQ-006 / AC-006 | P1 | 右侧每条绿色竖线对应一个可用 banked reset；0 不画，缺失为未知；不兑换 reset |
| REQ-007 / AC-007 | P1 | 原生“登录时启动”开关，初次不注册；状态由系统决定，待批准与错误明确显示 |
| REQ-008 / AC-008 | P1 | 5/15 分钟后台刷新，睡眠暂停；读取后关闭查询进程，串行查询、失败退避，无持续动画 |

FUNC-001：空状态保留一个灰色入口。所有已连接账户均出现在顶栏，取消置顶与手动选择周期。
FUNC-002：后台轮询、面板打开、唤醒、手动刷新共用刷新路径；同一账户和全量刷新分别防重入。
FUNC-003：网络失败保留旧快照并标识过期；未知值显示 `—` 和灰色轨道。
CON-001：Swift 6 工具链、macOS 13+、标准库与系统框架，无第三方依赖；不读取或输出令牌内容，不触发模型推理。
ASM-001：首次连接依赖本机可用登录；额外真实账户需要用户完成官方浏览器登录。中心百分比对应外环，两个精确数值在 tooltip 和详情中显示。
OOS-001：商店发布、公证、自动更新、多设备同步、历史趋势、自动切换 Codex 活跃账户、兑换 reset。

阶段门禁：当前需求与数据契约 → 核心模型及测试 → 原生界面和电源生命周期 → 构建/启动/证据 → 验收。门禁不等于等待用户批准；真实 OAuth、重启登录和长期耗电未验证则明确保留。

## ADR-001：原生实现

SwiftUI + AppKit，使用 NSStatusItem 彩色图像和 NSPopover。SwiftPM 直接使用本机工具链构建，无 WebView 或额外运行时。代价为仅支持 macOS，正式分发另需签名与公证。

ADR-002：采用低频、短连接刷新。默认 300 秒、系统低电量模式 900 秒，Timer 容差 20%；系统睡眠停止 Timer 和自有查询进程。唤醒/打开面板时复用最近 60 秒快照，手动刷新强制读取。多账户依次查询，读完终止子进程；失败按 5/10/20/40/60 分钟上限退避。以可接受的数据延迟减少后台唤醒和常驻内存。登录等待临时保留进程，最多 5 分钟。

ADR-003：登录启动使用 SMAppService.mainApp，由系统持有状态，不用自写 LaunchAgent；不在应用首次打开时偷偷启用。

## 模块

- MOD-001 / UsageCore：可空额度、reset、账户元数据、JSON 契约、显示语义和日期边界。
- MOD-002 / CodexClient：stdio JSON-RPC、分包、请求超时、进程退出、登录 URL 验证和清理。
- MOD-003 / UsageStore：账户隔离、元数据保存、首次连接、刷新、睡眠/电源状态和登录生命周期。
- MOD-004 / MenuBarController + Views：每账户状态项、可访问标签、详情与设置。
- MOD-005 / RingRenderer：菜单栏与面板共享原生绘制；中心字号按净空选择，reset 标记扩展图像宽度。
- MOD-006 / LoginAtLaunch：系统登录项适配，测试可注入替身，不修改真实登录设置。
- MOD-007 / RefreshPolicy：间隔、容差、缓存有效期和失败退避的纯规则。

## 输入输出契约

IN-001 / API-001：每行一个 UTF-8 JSON-RPC 消息；initialize/initialized 后 account/read 和 account/rateLimits/read。仅连接额外账户调用 account/login/start。递增 request id，错误保留诊断消息，不输出原始响应或凭据。

IN-002：usedPercent 为可空数值，合法数值钳制到 0–100；windowDurationMins 为可空分钟整数，resetsAt 为可空 Unix 秒。rateLimitsByLimitId 优先 codex，回退 rateLimits。类型错误抛解码错误。示例：`{"rateLimits":{"primary":{"usedPercent":28,"windowDurationMins":300,"resetsAt":1800000000}}}`。

API-002：AccountUsage 包含 RateSnapshot 与可空 bankedResetCount，后者来自 rateLimitResetCredits.availableCount，不能用可能不完整的明细数组长度推断；负数按未知。windowDurationMins == 300 才识别为 5 小时，与 primary/secondary 位置无关；另一个较长窗口放外侧，5 小时放内侧。只有 5 小时时单环显示 5 小时，不虚构周额度。

OUT-001：剩余 = 100 − 已用，四舍五入百分比，日期按系统时区。外环居中数字、内环弧长；未知 `—`，0% 保留轨道，100% 完整圆周。单环描边 2pt，双环描边 1.15/1.05pt，菜单图像直径 18pt、详情 36pt；每 reset 右侧一根与外环同宽的绿色竖线，间距 3pt。中心省略 %，详情与辅助功能保留单位。过期用系统灰色和文字说明。

IF-001：请求 30 秒超时；登录最多 5 分钟；取消/退出只停止本应用启动的进程。拒绝服务端意外工具请求。每个额外账户独立 CODEX_HOME；本机账户复用现有登录且无登出操作。

OUT-002：Application Support/Codex Usage Rings/settings.json 仅保存账户 ID、显示名、来源、autoConnectLocal，以及 autoHideEnabled / autoHideDelaySeconds 收起偏好。旧 kind=demo 仅用于迁移读取，随后过滤；损坏设置保留不覆盖。凭据由 Codex 保存在独立 profiles 目录，不进入仓库。

IF-002：SMAppService 状态 enabled 为生效，requiresApproval 保留开关开启意图并提示批准；注册/注销失败显示错误后重新读取系统状态。开关默认仅查询状态，无注册副作用。

## 0.3 界面细节修订

GOAL-003：依据用户的实际桌面截图缩小圆环，并让面板收起时间可控。

- REQ-013 / AC-013：菜单环 20pt、详情环 36pt；单环与 reset 线变细，中心只显示 0–100 的数字或未知符号，详情与辅助功能仍带百分比单位。
- REQ-014 / AC-014：鼠标移出后默认 3 秒收起；设置可关闭或设为 1–300 秒，自动保存并兼容旧设置；移入、编辑文字、关闭面板时取消倒计时。
- REQ-015 / AC-015：展开/收起采用原生 popover 过渡，遵循减少动态效果；切换账户不先关闭再打开；不引入周期动画或后台鼠标轮询。

IN-004：autoHideEnabled 为 Bool，默认 true；autoHideDelaySeconds 为 Int 秒，默认 3，钳制到 1–300。旧 JSON 缺失新字段采用默认值；非法类型保留既有损坏文件保护。示例：`{"profiles":[],"autoHideEnabled":true,"autoHideDelaySeconds":5}`。

ADR-005：用指针进出事件与一个可取消的一次性 Timer 驱动收起，而非轮询鼠标。原生 NSPopover.animates 提供系统过渡；不实现自定义逐帧动画。MOD-008 / PanelAutoHide 持有可见、指针、编辑与延迟状态，可注入调度器测试取消和过期回调；MOD-004 连接 SwiftUI hover/focus 与 popover 生命周期。

TC-013：0/100/未知和单双环绘制净空、浅深色离屏渲染；TC-014：设置迁移、范围和持久化、移出/移入/编辑/关闭/禁用时的调度与取消；TC-015：原生过渡配置与切换账户代码检查，实际桌面动画观感单列证据，不能由离屏图代替。

## 0.4 余量颜色与紧凑排版

GOAL-004：用颜色快速识别剩余额度，并进一步降低顶栏圆环高度。

- REQ-016 / AC-016：按显示的剩余整数分段：75–100 绿、50–74 蓝、25–49 黄、0–24 红；内外环分别按各自额度取色，详情条一致；未知和过期保持灰色，不将未知标成危险。
- REQ-017 / AC-017：顶栏直径 20 → 18pt；reset 竖线继续为绿色，实际线宽与当前外环完全相同，数量语义不变。
- REQ-018 / AC-018：在真实系统字体下比较 `100` 与 `Full` 的尺寸并提供可见对照；用户确认 `100` 尽量大但不碰环线。使用实际字形边界适配净空，保留数字百分比和 VoiceOver 语义，不将 Full 作为运行时模式。
- OOS-002：本轮刷新时间仅讨论，不变更默认 300/900 秒、缓存、退避或增加刷新设置；秒级轮询耗电尚无测量，不虚构耗电倍数。

MOD-001 增加可测试的 UsageBand 分段；MOD-005 共享配色与尺寸计算，MOD-004 的额度条复用配色。颜色依据四舍五入后的可见数字，防止 74.6 显示 75 却仍为蓝色。合法输入沿用 UsageWindow 余量归一化，缺失/非有限数值为 unknown。

TC-016：阈值两侧、0/100、四舍五入、非有限/未知；TC-017：单双环 reset 同宽、18pt 图像、标签净空及浅深色边界/排版对照。渲染仅用于测试，运行应用不加入演示或比较模式。

关于刷新周期的讨论结论（尚未实施）：当前每轮查询启动并关闭 Codex app-server，秒级轮询会增加进程启动、网络及 CPU 唤醒；理论上每账户1分钟/5秒/1秒分别60/720/3600轮每小时，实际会受延迟、防重入与退避限制，这不是耗电倍数。可考虑30秒、1/2/5/15分钟档位，默认1分钟，低电量模式降频；建议值是产品取舍，并非 Apple 统一规定。真正推送需另行验证数据源和跨账户更新能力。Apple 推荐优先事件通知、减少定时器并配置容差：[Minimize Timer Usage](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/Timers.html)。本轮不实现刷新设置，不进行真实电量对比测量。
